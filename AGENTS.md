# Less Bar product principles

User-confirmed direction: Less Bar is an extremely simple, minimal menu bar utility.

- Prefer intuitive controls and whitespace. Keep animated examples inside a collapsed How to Use section; loop seamlessly only while visible and respect Reduce Motion. Place descriptions below titles and above compact menu-bar examples; omit Replay, section labels and floating Command badges. The placement loop must drag left, hide, reveal and drag back right.
- Keep constraint explanations in accessible info buttons beside the affected control, shown only when that control is locked. Use standalone “Hover to Show Icons” / “Click Empty Space to Show Icons” labels (Korean: “마우스를 올리면 아이콘 표시” / “빈 공간을 클릭하면 아이콘 표시”) without a group heading. Keep menu-bar empty-space context in tooltips.
- Put Launch at Login and Show Arrow directly below the logo, followed by whitespace (no divider) and collapsed Advanced, Language and How to Use rows, in that order with identical spacing. Put hover, click, automatic hiding and always-expanded Timing sliders inside a collapsed Advanced / 고급 설정 disclosure. Turning Show Arrow off opens Advanced; users can collapse it again. Provide How to Use / 사용 방법 in the native context and app menus; it opens the existing settings window with the guide expanded, even after manual collapse or window close.
- Keep only essential settings. Do not add marketing copy, numbered onboarding, repeated instructions, version footers or duplicate actions to the main settings view.
- Keep instructional illustrations visually separate from real controls; examples must not look like draggable or clickable controls. Use explicit action labels rather than ambiguous icon-only buttons in settings.
- Keep visibility controls synchronized with the actual menu bar engine, including recovery.
- Offer System Default, English and 한국어 as mutually exclusive native radio buttons inside a collapsed Language / 언어 disclosure. The whole label row must toggle it. Apply language changes immediately across settings and native menus, persist the choice, and keep system language unchanged.
- Show Less Bar in Dock and ⌘Tab while Settings is open, including when minimized or inactive. Return to menu-bar-only mode when Settings closes.
- Each disclosure header is one full-width keyboard-accessible button, including the arrow, arrow-label gap and trailing space; content controls must not toggle the header. Disclosure sections expand and collapse smoothly from the bottom while the window's top stays fixed. Keep window sizing separate from the disclosure's intrinsic-height animation to avoid jitter; respect Reduce Motion.
- Hover or a hidden chevron requires automatic hiding. Preserve the independent automatic-hide choice across relaunches and restore it when the chevron is shown with hover off. Keep the hide delay adjustable.
- Keep Show Icons / Hide Icons out of both settings and menus. Only Quit has an app shortcut (⌘Q); Settings has none. Preserve native keyboard navigation and reopen-to-reveal recovery.
- Use “Show Arrow” / “화살표 표시” in user-facing text, as a text-only setting label without a decorative arrow glyph. Keep internal preference keys stable.
- Show Arrow, Hover to Show Icons and Click Empty Space to Show Icons are independent. With the chevron shown, both empty-space methods may be off; with it hidden, at least one must stay on. Hiding the chevron with both off enables Click. Both methods may be on together. Missing Accessibility permission always keeps the chevron visible. Preserve native right-click menus, reopen recovery and Command editing. The rounded bar-and-dot LESS mark is the brand logo.
- Follow macOS native menu UI conventions. Use standard NSMenu / NSMenuItem for the settings/help/quit menu; let the system control spacing, typography, highlighting and keyboard behavior. Do not replace menus with custom popovers or add blank items for padding. This takes priority over custom menu spacing preferences.
- Keep active screen-sharing indicators visible and clickable. Prefer them to the right of the chevron, but do not claim guaranteed expanded-state ordering without a verified implementation. Do not cover system indicators or move the hide boundary to a different group just to mimic this order.
- Preserve keyboard access, accessibility labels and necessary error/unsupported-state feedback. Minimalism must not remove recovery or hide failures.
- Brand: Less Bar (with a space) in all user-facing names and app bundles. Preserve the LessBar Swift module/executable, io.github.devnjw.LessBar bundle ID, existing preference/placement keys and repository URLs for compatibility. Audience: global individual Mac users. Target price: US $0.99 one-time. Early promotion: free coupons. No extra tiers or feature expansion without a user request.
- Publication decision (2026-10-11): public GitHub repository under devnjw with the MIT license. Initial GitHub previews are free; do not imply an implemented paid checkout. Keep installation instructions in English and Korean and distinguish notarized releases from development builds.

These preferences should guide future design and implementation in this repository.
